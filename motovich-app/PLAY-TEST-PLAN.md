# MOTOVICH — план закрытого тестирования и Data safety

Этот документ — рабочий план для первого Android-релиза. Не считать тест завершённым, пока проверки реально не выполнены на подписанной Android-сборке.

## 1. Подготовить тестовый трек

1. Загрузить release AAB в Internal testing, установить его на Android-телефон и проверить базовые сценарии.
2. Когда основные ошибки устранены, создать Closed testing в Play Console и пригласить тестировщиков по списку email или Google Group.
3. Для нового личного аккаунта Google Play, созданного после 13 ноября 2023 года, нужно минимум 12 тестировщиков, которые **непрерывно остаются opted-in не менее 14 дней**, прежде чем запросить production access. Самого добавления email в список или однократной установки недостаточно. Рекомендуется пригласить 15–20 людей с запасом.
4. Не удалять тестировщиков без необходимости и не менять трек так, чтобы потерять их непрерывный период. Если тест не длится достаточно долго, исправление кода не возвращает прошедшее время, если нужные тестировщики не оставались подписанными на закрытый тест.
5. Собрать реальные отзывы, записи проблем и список исправлений. Play Console может спросить, что проверяли и какие выводы сделали.

Официальные требования: https://support.google.com/googleplay/android-developer/answer/14151465

## 2. Тест-кейсы

Отмечайте каждый сценарий только после проверки на актуальной подписанной Android-сборке или установленной версии из тестового трека.

| ID | Сценарий | Ожидаемый результат | Статус |
|---|---|---|---|
| T01 | Первый запуск приложения | Главная открывается без JS-ошибок, нет белого экрана | Не проверено |
| T02 | Создать, изменить и удалить задачу | Изменения сохраняются после перезапуска | Не проверено |
| T03 | Создать голосом «завтра в 10 позвонить…» | Задача появляется в списке и на соответствующей дате календаря | Не проверено |
| T04 | Диктовать несколько задач | Каждая задача создаётся отдельно, нет дубликатов | Не проверено |
| T05 | Выбрать задачу в календаре | Можно завершить, редактировать и удалить нужную задачу | Не проверено |
| T06 | Включить режим полёта | Локальные задачи и разделы работают офлайн после первого успешного кэширования | Не проверено |
| T07 | Обновить версию сайта/PWA | Обновлённые скрипты загружаются, старый кэш не ломает запуск | Не проверено |
| T08 | Экспортировать и импортировать резервную копию | Валидный файл восстанавливает данные; неверный JSON не ломает приложение | Не проверено |
| T09 | Запустить на реальном Android-телефоне | UI адаптирован под реальные размеры экрана и Android-клавиатуру | Не проверено |
| T10 | Подключить реальный Supabase-проект | Регистрация, вход и ручная синхронизация работают; чужие записи недоступны | Не проверено |
| T11 | Разрешить Push и нажать тестовую отправку | Push приходит на устройство; закрытие приложения не блокирует системную доставку | Не проверено |
| T12 | Создать задачу на 2–3 минуты вперёд и выгрузить данные в облако | Напоминание приходит в ожидаемое время один раз | Не проверено |
| T13 | Создать задачу без времени | Она не получает напоминание на случайный час | Не проверено |
| T14 | Изменить дату/время после выгрузки | После повторной выгрузки используется обновлённый срок; старый срок не считается текущим | Не проверено |
| T15 | Отключить Push на устройстве | Подписка этого устройства отключается; локальные задачи не удаляются | Не проверено |
| T16 | Удалить облачный аккаунт | Аккаунт и его cloud state/Push-подписки удаляются; локальная копия остаётся | Не проверено |
| T17 | Открыть внешний URL удаления без входа | Пользователь видит рабочий способ запросить удаление даже после удаления приложения | Блокер: нужен реальный адрес поддержки |
| T18 | Открыть политику конфиденциальности | Страница открывается без аккаунта и соответствует включённым серверным функциям | Не проверено |
| T19 | Проверить полноэкранный TWA-запуск | Нет адресной строки браузера; Digital Asset Links совпадает с package ID и Play signing fingerprint | Блокер: root assetlinks даёт 404 |
| T20 | Проверить финальный target API | В подписанном Android App Bundle target API 36 или выше | Не проверено |

Для T12 используйте тестовую задачу только на своём устройстве и удалите её после проверки. Не включайте массовую рассылку или cron всем пользователям до проверки, что секреты и подписки принадлежат правильному проекту.

## 4. Черновик для Data safety

Это не финальная декларация. Внести ответы в Play Console **после** выбора настоящей сборки и проверки реальной Supabase-конфигурации.

- **Личные задачи, привычки, цели, дневник, заметки, самочувствие:** по умолчанию локальное хранилище браузера; при ручной облачной синхронизации JSON-состояние передаётся в настроенный Supabase-проект.
- **Email/учётная запись:** если включена опциональная регистрация, Supabase Auth обрабатывает email и состояние аутентификации. Приложение хранит сессионные токены локально, пока пользователь не выйдет или сессия не истечёт.
- **Push-подписки:** после явного согласия проекта сохраняет endpoint и ключи подписки, нужные для отправки уведомлений; сервер использует их для доставки.
- **AI-коуч:** при включённом серверном AI функция получает текст запроса и компактный контекст (число открытых задач и уровень энергии), но не загружает названия и полный текст задач. Настроенный endpoint передаёт запрос провайдеру модели.
- **Реклама / аналитика:** в клиентском коде этой версии не выявлены рекламные SDK. Повторно проверить финальную сборку и подключённые библиотеки перед декларацией.
- **Шифрование:** перед отметками о шифровании при передаче проверить HTTPS во всех endpoint и фактические серверные соединения.
- **Удаление:** есть действие внутри приложения для удаления облачного аккаунта, но внешний путь удаления ещё не готов к публичной версии, пока не указан реальный контакт поддержки. Не заявлять полное соответствие этой политике, пока это не закрыто.

Официальная справка Google Play: https://support.google.com/googleplay/android-developer/answer/10144311 и https://support.google.com/googleplay/android-developer/answer/10787469

## 5. Стоп-лист перед production-релизом

- [ ] Создать подписанный AAB с targetSdk 36 или выше.
- [ ] Решить root origin для TWA и опубликовать корректный /.well-known/assetlinks.json с реальным package ID и SHA-256 сертификата Play App Signing.
- [ ] Добавить и проверить реальный контакт поддержки и внешнюю ссылку запроса удаления аккаунта.
- [ ] Настроить production Supabase project, применить все три миграции, секреты, пять Edge Functions и cron; проверить тестовое Push-уведомление и реальный срок задачи.
- [ ] Проверить политику конфиденциальности, Data safety, доступ ревьюера, рейтинг контента и карточку магазина.
- [ ] Подготовить настоящие Android-скриншоты и feature graphic.
- [ ] Проверить smoke-тест, отчёт pre-launch и отсутствие критических ошибок.
- [ ] Если на аккаунт распространяется правило закрытого тестирования, получить 14 непрерывных дней участия минимум 12 тестировщиков и затем запросить production access.
